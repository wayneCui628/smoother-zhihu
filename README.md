# 知乎顺滑器

一个面向 Chromium 浏览器的轻量扩展，用来缓解知乎网页版超长问题页越滚越卡的问题。

## 它如何工作

扩展只在知乎问题页运行，并分两层降低浏览器负担：

1. 记住已经真实渲染过的回答高度；未获得可靠高度前保持回答正常渲染，不使用固定估算值冒险占位。
2. 当回答数量较多时，用视口观察器冻结远离当前视口且高度已经确认的回答；节点仍由知乎 React 管理，接近视口时原地恢复，避免替换 DOM 导致页面失稳。
3. 只监听知乎真实回答列表的直接子节点，增量接收新回答；知乎批量追加回答时，每个动画帧最多注册一个新节点，避免把插件工作叠加到同一帧，也不在每次滚动时重新扫描整页。
4. 内容脚本先读取保存的配置再启动虚拟化；暂停状态不进行预扫描。
5. 完全隐藏回答流中的第三方广告和知乎站内推广，同时保留 React 容器所有权和末尾的无限加载触发器，避免知乎更新列表时崩溃。
6. 在页面右下角用默认收起的轻量摘要条展示优化效果，展开后查看完整统计。

第二层保留的是原始节点，而不是复制出的 HTML，因此回答本身的事件监听和已加载状态可以随节点恢复。扩展不会读取、上传或分析回答内容。

## 本地安装

1. 打开 Chrome 或 Edge 的扩展管理页。
   - Chrome：`chrome://extensions`
   - Edge：`edge://extensions`
2. 打开“开发者模式”。
3. 选择“加载已解压的扩展”，然后选择本项目根目录。
4. 打开一个回答较多的知乎问题页，正常向下滚动。
5. 点击工具栏里的“知乎顺滑器”，可暂停优化或调整保留范围。

修改代码后，在扩展管理页点击该扩展的“重新加载”，再刷新知乎页面即可。

## 开发与验证

项目没有运行时依赖，也不需要打包：

```powershell
node --test tests/manifest.test.js tests/virtualizer.test.js tests/content.test.js tests/page-widget.test.js
```

当前原型支持：

- 知乎问题页动态追加回答；
- 隐藏回答列表中的第三方广告和知乎站内推广，不占滚动空间、不可交互；
- 识别并保护知乎末尾的零高度加载触发器；
- 评论展开、收起和继续加载时更新回答的真实高度；
- 保留知乎超长回答原生的底部悬浮操作栏，可继续打开评论或收起回答；
- 暂停时完整恢复已暂存回答；
- “恢复本页全部回答”只暂停当前标签页，刷新页面或重新开启后继续优化；
- 2、4、6 个视口高度的保留范围；
- 页面悬浮窗默认收起，并根据知乎右下角原生按钮的实时位置动态避让；空间不足时自动移到按钮上方，可展开查看完整统计，也可在扩展弹窗中关闭；
- 弹窗内显示回答总数、当前保留数和暂存数；
- 知乎单页应用导航后的重新扫描。

## 已知边界

- 识别逻辑基于当前知乎问题页的 `.QuestionAnswers-answers`、回答 `data-zop.itemId` 和末尾 `role=listitem` 加载触发器；知乎改版后可能需要同步更新。
- 扩展会临时固定高度刚刚变化（例如评论正在展开、图片加载导致高度增长）或内部有键盘焦点的回答，避免冻结在过期高度上；高度稳定数秒后回答会重新纳入冻结范围。
- 超长回答的真实高度只用于自身冻结，不参与其他回答的估算，避免少数长内容把整页滚动高度放大。
- 尚未真实渲染、无法确认高度的回答不会被冻结；扩展也不会主动改写页面滚动位置，避免上下滚动时跳动或回弹。
- 知乎自身仍会在列表底部一次请求并插入多条回答；扩展会分帧处理自己的注册工作，但不会拦截知乎接口或改写返回数据，因此不能完全消除网站原生批量插入造成的瞬时峰值。
- 广告和站内推广的 React 容器会留在 DOM 中但保持 `display: none`；直接删除会使知乎随后执行 `removeChild` 时抛错并进入“出了一点问题”页面。
- 扩展目前面向 Chrome / Edge；Firefox 尚未纳入首版验证范围。

## 隐私

扩展只申请 `storage` 权限来保存开关和保留范围。它不包含远程代码、统计 SDK 或网络请求。
